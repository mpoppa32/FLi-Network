## WRITE LAYER — P13.398 (2026-08-06), wedge-proofed for real

**FIXED, harness-verified; live acceptance owed.** `fbSet`/`fbRemove` previously hung forever on a wedged socket: the SDK promise was fired fire-and-forget, the REST path returned early **only on `_r.ok`** (so an RTDB 503 fell through), and the last line then `await`ed that same never-settling promise. A hang never rejects, so nothing reported it — **meeting PROCESS stalled at "Analyzing" with no error, no console output and zero requests to `anthropicProxy`**, because `saveMeeting` → `fbSet` is the first `await` in the process path. Reproduced twice 2026-08-06. CT-4's `persist_error` was blind to it too (it sits in a `catch`).

- **The structural fix:** REST is now **authoritative**, not a preferred-but-optional path. A non-ok response is a failure to surface, never a reason to fall back — the old logic treated "REST 503" as "REST unavailable, use the SDK", but under a wedge those conditions **co-occur on one broken network**, so the safety net handed control to the hung path in exactly the case it existed for. The SDK write remains optimistic (instant local update + `onValue`) but is **raced against `FB_WEDGE_MS` (8s), never awaited unbounded** — a hang is detectable only by clock, never by `.catch` (the CT-1b/P13.397 lesson). `getIdToken()` is itself a network call and is timed out too; the REST `fetch` carries an `AbortController` deadline.
- **Rule 11 surfacing on failure:** `setSS('error')` + `console.error` naming *both* paths + a `persist_error` health event + an operator toast, then a **throw** — so callers like the process path's `try/catch` (`26430-26436`) finally fire instead of waiting forever. Wording is deliberately "could not confirm write", not "write failed": a timed-out SDK write may still land later.

## WORKSPACES
Fully dynamic (`workspaces/{wsId}`). No hardcoded FLi/Atlas IDs. FLi and Atlas are the two operational workspaces in practice. Firebase paths: `workspaces/{wsId}/{meetings,nodes,links,entities,cal,commitments}`.

`wsPath(sub)` returns `'workspaces/'+currentWsId+'/'+sub`. **`currentWsId` is assigned in exactly one place — `selectWorkspace(wsId)`.** Everything that reads or writes workspace data depends on that single module-level variable.
